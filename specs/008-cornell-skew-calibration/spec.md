## Requirements

- **FR-1 — Reproducible baseline.** Report input identities, processed physical coincidence count, prefix/full-file selection, accepted count, calibration/map/config fingerprints, seeds, hardware/storage, compilation/startup, decoding, feature selection, geometry, accumulation, solve and output time. Compare identical records/cuts; never compare a 500,000-record prefix with a full-file run as if workloads matched.
- **FR-2 — Geometry contract.** Separate active shell inner/outer radii, center, axis and axial extent from detector interaction geometry. Confirm the meaning of `ring_r`, local origin/orientation, spatial calibration and axial placement before reporting a physical calibration. Unknown required geometry yields an unavailable result, not a guessed detector radius.
- **FR-3 — Skew convention.** Declare `y=t_i-t_j`, positive delay `b_i`, corrected timestamp `t_i-b_i`, and export convention. Verify positive injected delays and endpoint swaps through the real downstream consumer. Existing additive tables need an explicit migration/sign decision; never silently reinterpret them.
- **FR-4 — Streaming reader.** Expose compiled LDAT batches with variable hit counts, raw int64 timestamps, float32 hit energies, int32 channel IDs and event/side boundaries. Memory is bounded by configured chunk size, lookup tables and bounded accumulation/cache buffers; never retain all accepted file rows in RAM. Preserve malformed/empty/truncated input diagnostics and release memory maps on failure.
- **FR-5 — Selection parity.** A reference mode reproduces existing selection order, maximum-energy minimodule/time hit, slab rules, strict keV bounds on both detectors, coincidence window and the legacy 3D opposition-angle cut (at least 165 degrees). Record energy/angular definitions and rejection counts; test exact boundaries and distinguish 3D from transverse-only angle. Alternate energy/angle selections require separate comparison of offset bias/uncertainty and channel-graph coverage on frozen validation data. Explicitly record that the legacy script reads but does not apply `en_min_ch`. Applying the configured cut is an intentional analysis change, separately compared. Seed ambiguous slab decisions reproducibly across chunk/worker configurations; report ties and ambiguity.
- **FR-6 — Complete and safe processing.** Replace the hidden 500,000-record/file stop with an explicit optional limit; full-file processing is the production default. Account for every rejection once. Missing/invalid calibration, unknown map channels and impossible geometry produce reasoned rejections/failures. Configured unpopulated regions follow the selected map/config; record owner-confirmed acquisition-specific down hardware separately and exclude it from operational coverage targets without fabricating measurements.
- **FR-7 — One record, one observation.** Count and retain each accepted physical coincidence once. The two shell intersections are alternative source hypotheses; reversed endpoint views and alternatives do not inflate statistics. Pair/histogram counts use an overflow-safe representation.
- **FR-8 — Bounded cache and restart.** Use versioned, independently completed numeric blocks and a provenance manifest. Reuse only matching inputs, map, energy/spatial calibration, geometry, cuts, seeds and schema. Preserve old CSV/checkpoint/user outputs; partial blocks never look complete. Solver iterations require no new LDAT decoding when required features exist in the cache.
- **FR-9 — Shell pair estimates.** Estimate channel-pair differences from both shell peaks with separate amplitudes and geometric midpoint correction. Preserve relevant event geometry within each fit; one channel pair can cover many LORs. Treat finite wall thickness, axial boundaries, overlap and background explicitly. One unresolved peak or a failed fit is insufficient information, not zero offset.
- **FR-10 — Global channel solve.** Solve pair differences simultaneously using uncertainty-weighted sparse constraints, an explicit gauge and optional robust loss. Report connected components, channel coverage, pair fit quality, uncertainty and residual consistency. Disconnected components have unobservable relative origins and must not appear globally aligned.
- **FR-11 — Optional model refinement.** Compare finite-shell distribution/likelihood matching with the midpoint solution only if held-out evidence justifies it. Sum/integrate branch likelihoods, retain geometry dependence and explicit nuisance/background assumptions. Report shell-only timing width as model dependent.
- **FR-12 — Channel validity.** Distinguish calibrated, low-statistics, disconnected, ambiguous, failed-fit and unobserved channels in a status artifact. Do not feed `9999`, missing values or invented zeros into correction arithmetic. A legacy-format adapter must be explicit and consumer tested.
- **FR-13 — CTR validation.** Freeze offsets and evaluate disjoint events/acquisitions with identical cuts. Prefer a known-position point/recorded rotating-line source for geometric TOF subtraction. Report pooled residual FWHM, fit model, uncertainty, tails, coverage, physical count and weighting. Neither raw shell histogram FWHM nor nearest-branch residual selection constitutes independent CTR.
- **FR-14 — Performance and numerical acceptance.** Publish Cornell local-disk stage timings, throughput, total job time and parent/worker peak memory; include warm and first-call costs. Check deterministic decoding/selection and known-delay recovery before speed comparisons. Provisional targets: at least 10x warm decode/feature throughput and 3x complete-job improvement when below the measured storage ceiling; missed targets require a documented stage breakdown and owner review, not an unsupported speed claim.
- **FR-15 — Retirement and compatibility.** Keep one supported entry point, with tracked numerical implementation/tests and a thin local launcher. Verify Inspector reader behavior and Cornell consumers before retiring `cornell_skew_cal_bigdata_optimized.py`. Preserve its existing outputs and all acquisition/config/map/untracked work. No commits, pushes, release builds or unrelated GUI changes.
- **FR-16 — Run 7 qualification and data sufficiency.** Inventory every converted split in the successful conversion ledger (16 actual outputs from requested setting 15) using actual input identities, chronological coverage and conversion metadata. Report coincidence records, first-failure cut counts, accepted observations and counts per operational TIME channel, partner/geometry coverage, usable shell-peak constraints, connected components and estimated offset uncertainty. Use disjoint recorded train/validation/test time blocks and a training-size convergence study to classify the dataset as sufficient, sufficient for a named channel subset, or insufficient with specific reasons. Do not infer calibration adequacy from RAWF size/duration or extrapolate from a first-file prefix. Retain acquisition/rate/hardware-availability provenance; same-run holdout alone does not prove rate independence or independent point-source CTR. - **FR-17 — Canonical LUT and PETsys export.** Deliver global TIME-channel IDs, subtractive delays in ps, gauge, uncertainties and explicit validity statuses. A later native adapter must verify the installed PETsys version's channel identity, table schema, units, activation settings and correction order against upstream evidence and a bounded RAWF conversion check. Verify positive injected delays and endpoint swaps; apply correction once. Preserve existing calibrations and define treatment of other/invalid channels explicitly. Because native correction precedes hit grouping/coincidence selection, compare matched retained events and separately report changed membership/counts; never require all corrected and uncorrected LDAT records to be identical. Adapter failure leaves native-export qualification pending, without invalidating a separately qualified canonical LUT.
- **FR-18 — Pooled multi-run job.** One tracked, resumable command takes an explicit job file listing run directories with their conversion ledgers, config/map, the reused `.encal`, acquisition-specific down regions, the selected geometry and a cache/output directory, and runs inventory, frozen per-run file roles, feature caches, observation sets, pooled pair fits, global solve and canonical LUT without user edits between stages. Each run keeps its own identities, inventory, roles (frozen before fitting), first-failure counts and coverage. Pair fits pool train events of all runs per channel pair; validation/test stay per run. Report per-run energy-peak positions against r7 and flag a shift beyond a declared tolerance; a run whose peak moved may use its own `.encal`, with its held-out prefix taken from the calibrate run that produced it. Report per-run train/validation residuals against the pooled delays and, optionally, solve each run alone and compare its delays with the pooled and reference-run solutions after gauge alignment, so a rate-dependent offset is visible even though the LUT is pooled. With per-run solves, a per-run reproducibility floor is estimated from all run pairs and its statistics-weighted pooled share is added in quadrature to each applied channel's uncertainty before gating; channels whose run-alone delay departs from the pooled one by more than a declared threshold are listed in the report and LUT manifest. Test files are not evaluated by the job. Disk use is checked before writing and bounded by the per-run caches; memory stays bounded as in FR-4/FR-8. A missing or failed run stops the job explicitly rather than silently shrinking the pool.
- **FR-19 — Per-ASIC skew diagnostics.** Each job LUT, and on request any existing canonical LUT, gets per-ASIC diagnostics of its applied delays, decoding global TIME-channel IDs into PETsys port/slave/chip/channel: a within-ASIC overlay (delay minus ASIC median against channel index 0-63, with the across-ASIC median and 16-84 % band), an ASIC x channel heatmap, an overview by port and ASIC, and per-ASIC median delay and slope, as PNG files next to the LUT, plus a per-ASIC summary table. A channel whose delay departs from its ASIC median plus the across-ASIC median for its channel index by more than a declared threshold (default 1 ns) is listed in the job report and LUT manifest; statuses and applied delays are unchanged. Existing outputs are never overwritten. These plots are diagnostics, not validation evidence.
- **FR-20 — Second pass on natively corrected data.** A job run entry may name a native-conversion manifest instead of a conversion ledger; it lists the split files (index, name, size), the native table and its manifest (SHA-256, source canonical LUT SHA-256), the activated INI that names exactly that table, and the declared RAWF source and converter command. All runs of a job share one correction state (uncorrected, or the same native table); mixed states are refused. Held-out `.encal` prefixes of corrected runs are the uncorrected `records_validated` counts matched by split index, enlarged by a declared margin (2 %). The LUT solved from corrected data is a **residual** LUT whose manifest records the input correction; it is never exported as a native table nor applied to uncorrected data. With the source canonical LUT of the native table (SHA-256 must match), the job also writes a composed LUT for uncorrected data: `b_native + b_residual` where the residual is applied (uncertainty and status from the second pass), the native offset with the source row where only the first pass has a delay, and the residual alone where only the second pass does; counts per source are recorded. The report gives the residual distribution (gauge-aligned z RMS, quantiles), its trend against the native offset (weighted slope, bins of |b_native|), pair chi2 in bins of |native pair shift| (the first-pass window-clipping signature), ASIC channel 11/13 group means and the residuals of the source LUT's listed outliers.

## Completion criteria

All requirements have a passing named check and documented limitations. Known synthetic delays recover exactly in the noiseless case after fixing the gauge; noisy/asymmetric-source fixtures recover within declared uncertainty.
